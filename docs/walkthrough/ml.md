# ML pipeline walkthrough

`tools/record_dataset.py` is the human recording interface. It captures 16 kHz mono `int16` WAV files through the optional `sounddevice` backend, trims low-energy leading/trailing samples, flags clipping, and appends `metadata.csv` plus provenance. If the backend or microphone is unavailable it exits without writing audio. `ml/dataset.py` validates metadata and constructs leave-one-speaker-out partitions. `ml/features.py` supplies MFCCs. `ml/model.py` defines the DS-CNN-small architecture; `ml/train.py` loads real WAVs and trains it once TensorFlow and labelled metadata exist; `ml/export_tflite.py` requires representative features and emits a fully-int8 C array. Both commands write explicit `NOT_A_RESULT` blocker status files when prerequisites are absent.

Viva questions: Why leave one speaker out? To measure unseen-speaker generalisation. Why record distance and room? To stratify acoustic conditions. Why a closed vocabulary? It fits MCU memory and safety constraints. Why confidence gating? Low-confidence commands must never act. What is currently reported? Only metadata/synthetic pipeline checks, never accuracy.
